# Pyloxa 0.1.7

This is a security update. Please update from 0.1.6 or earlier.

## Security fixes

A security review found four problems in Pyloxa 0.1.6 and earlier. We have no reports of any of them being used.

- **Opening a project could run a program from that project.** Pyloxa started `git` and `gh` by name, and Windows looks in the current folder first. A repository that contained its own `git.exe` could have that file run as soon as you opened the project in Pyloxa. Pyloxa 0.1.7 starts git, gh and the Windows tools it uses only from where they are installed.
- **A project's agent settings were loaded without asking you.** Pyloxa runs Claude Code and Gemini CLI without an interactive window, so their own "Do you trust this folder?" question never appeared. A project's `.claude/settings.json`, `.claude/settings.local.json`, `.gemini/settings.json` or `.gemini/.env` was loaded whenever work was dispatched, and these files can make the CLI run commands, connect somewhere else or loosen its permissions. Pyloxa 0.1.7 now asks first (see below).
- **Renaming `Pyloxa.exe` turned on developer-only options.** With a different file name, Pyloxa treated itself as a development build, which also re-enabled remote debugging that 0.1.6 had blocked. Pyloxa 0.1.7 recognizes a released build by how it is packaged, not by its file name.
- **Pyloxa could be told to show another web page as its interface.** Another program already running under your Windows account could start Pyloxa with the `ELECTRON_RENDERER_URL` environment variable, and that page got the same access as Pyloxa's own interface. Pyloxa 0.1.7 ignores this variable.

## Confirming a project's agent settings

When a project you open contains agent settings beyond the model and display options, a notice at the top of the window lists the files. Click a file name to review it, then choose **Trust**. Until you do, Pyloxa won't dispatch work in that project, and a task that tries explains why.

Pyloxa remembers the exact contents you trusted. If a file changes later, for example after a pull or because an agent's task edited it, Pyloxa asks again. Files that only set the model or display options don't need confirming.

## Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in `%APPDATA%\Pyloxa` are kept. This version doesn't change the data format.

## Known limitations

- Windows 10 and 11, 64-bit only.
- The installer is not code-signed. SmartScreen may warn you; choose **More info**, then **Run anyway**.
- No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
- Codex runs through `codex exec` in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
- Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
- Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

# Pyloxa 0.1.7（繁體中文）

這是一個安全性更新，請從 0.1.6 以前的版本更新。

## 安全性修正

安全審查在 Pyloxa 0.1.6 以前的版本找到四個問題，目前沒有收到任何一個被利用的回報。

- **開啟專案時可能執行專案裡的程式。** Pyloxa 以名稱啟動 `git` 與 `gh`，而 Windows 會先在目前的資料夾裡找。如果 repo 裡放了自己的 `git.exe`，你在 Pyloxa 開啟這個專案時，它就可能被執行。Pyloxa 0.1.7 只從安裝位置啟動 git、gh 與它用到的 Windows 工具。
- **專案的 Agent 設定檔沒有先問過你就被載入。** Pyloxa 在沒有互動視窗的模式下執行 Claude Code 與 Gemini CLI，所以它們自己的「信任這個資料夾嗎？」不會出現。專案裡的 `.claude/settings.json`、`.claude/settings.local.json`、`.gemini/settings.json` 或 `.gemini/.env` 會在派工時被載入，而這些檔案可以讓 CLI 執行命令、連到其他地方，或放寬它的權限。Pyloxa 0.1.7 會先問你（見下方說明）。
- **把 `Pyloxa.exe` 改名，會打開只供開發用的選項。** 換了檔名之後，Pyloxa 會把自己當成開發版，連 0.1.6 擋下的遠端除錯也會重新可用。Pyloxa 0.1.7 改以打包方式判斷是不是正式版，不看檔名。
- **Pyloxa 可能被要求把其他網頁當成它的介面。** 已經在你的 Windows 帳號下執行的其他程式，可以帶著 `ELECTRON_RENDERER_URL` 環境變數啟動 Pyloxa，那個網頁會拿到和 Pyloxa 介面相同的權限。Pyloxa 0.1.7 不再理會這個變數。

## 確認專案的 Agent 設定檔

你開啟的專案裡如果有模型與顯示選項以外的 Agent 設定，視窗上方會出現提示並列出這些檔案。按檔名可以檢查內容，確認後按「信任」。在那之前，Pyloxa 不會在這個專案派工，嘗試派工時也會說明原因。

Pyloxa 記住的是你信任時的檔案內容。之後檔案有變動（例如 pull 之後，或 Agent 的工作修改了它），Pyloxa 會再問一次。只設定模型或顯示選項的檔案不需要確認。

## 升級

直接執行新的安裝檔覆蓋舊版即可。存在 `%APPDATA%\Pyloxa` 的執行紀錄、專案、設定與保存的 API Key 都會保留。這個版本沒有改變資料格式。

## 已知限制

- 只支援 Windows 10 與 11（64 位元）。
- 安裝檔沒有程式碼簽章，SmartScreen 可能跳出警告；請按「其他資訊」，再按「仍要執行」。
- Pyloxa 本身不會自動更新。有新版本時 Pyloxa 會提示你。
- Codex 透過 `codex exec` 在它的沙箱內執行。在 Windows 上，這個沙箱通常無法建置專案或安裝套件，所以 Codex 的成果以你的驗證命令驗收。
- Gemini CLI 是實驗性支援：不能擔任大腦或交叉測試的測試者，在無人值守模式下也不能執行命令。
- 已測試 Claude Code 2.1.318、Codex CLI 0.166.0，以及 Gemini CLI 0.66.0 與 0.67.0。
