# Pyloxa 0.1.4

This release fixes a billing safeguard for Gemini CLI 0.66.0 and later. If you use Gemini CLI, please update. It also tells you when your agent CLIs have new versions and can update them for you.

## Important: Gemini CLI 0.66.0 and later

Pyloxa runs Gemini CLI only with your own paid Gemini API key, never with a Google account sign-in or Google AI Pro or Ultra subscription. Gemini CLI 0.66.0 changed how it reads system settings, so Pyloxa 0.1.3 and earlier can no longer enforce this. If you signed in to Gemini CLI with a Google account, tasks sent to Gemini could use that sign-in instead of your API key.

Pyloxa 0.1.4 enforces API-key-only auth again:

- Each Gemini run uses a separate settings folder that Pyloxa creates and deletes afterwards. That folder allows only API-key auth. Your Google sign-in in `~/.gemini` is never loaded.
- If a project's `.gemini/settings.json` sets a different auth method, Pyloxa won't run Gemini in that project and tells you why.
- We tested this with Gemini CLI 0.66.0 on a computer whose Gemini settings chose Google sign-in. Pyloxa still used only the API key.

Until you update, don't send tasks to Gemini CLI 0.66.0 or later from Pyloxa 0.1.3 or earlier.

## What's new

- **New CLI versions.** The **Connections** page shows when Claude Code, Codex CLI or Gemini CLI has a new version, which version Pyloxa has verified, and a link to the official release notes. A banner tells you when a CLI's version changed since you last opened Pyloxa.
- **Update a CLI in one click.** When a newer verified version is available, **Update to x.y.z** runs the CLI's official install command after you confirm: `claude install` for Claude Code's native install, or `npm install -g` for npm installs. Pyloxa won't update a CLI while it has tasks running. If Pyloxa can't tell how a CLI was installed, it shows a command you can copy instead.
- **Verified versions update without a new Pyloxa.** Pyloxa reads a small compatibility catalog from GitHub with its update check, so newly verified CLI versions, model suggestions and notices reach you without waiting for a Pyloxa release.
- **Skills matrix.** The **Skills** page now shows each skill as a row and each agent as a column, compared against your Skills library in `~/.agents/skills`. Each cell shows whether the skill is in sync, installed, different or missing. Click a skill to read its `SKILL.md`, see its files, or show it in File Explorer.
- **What's new after an update.** After you update, a banner links to the changelog on pyloxa.com, and the new-version banner has a **See what's new** link. The full history is at [pyloxa.com/changelog](https://pyloxa.com/changelog/).

## Privacy and safety

- The compatibility catalog is read from GitHub together with the update check, at startup and every 12 hours. Only these two requests are sent, with no project or usage data. Both are turned off by **Settings → Notifications and updates**.
- One-click updates change the same CLI you use outside Pyloxa. They only run the official install command shown in the confirmation.
- Gemini runs in Pyloxa no longer load your own Gemini settings, MCP servers, extensions or hooks, and Gemini's usage statistics are turned off for these runs.
- In the free version, the **Skills** page reads skills folders and changes nothing. Adding, syncing, editing and removing skills are part of the paid version, which isn't available yet; those buttons show a lock.

## Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in `%APPDATA%\Pyloxa` are kept.

## Known limitations

- Windows 10 and 11, 64-bit only.
- The installer is not code-signed. SmartScreen may warn you; choose **More info**, then **Run anyway**.
- No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
- Codex runs through `codex exec` in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
- Gemini CLI support is experimental. It can't act as the brain and can't run commands in unattended mode. Its built-in sub-agents can use a lot of tokens: in our tests, a one-file task that called a sub-agent used about 340,000 tokens.
- Tested with Claude Code 2.1.316–2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.42.0 and 0.66.0.

# Pyloxa 0.1.4（繁體中文）

這一版修正 Gemini CLI 0.66.0 以後的費用保護；如果你有用 Gemini CLI，請更新。另外，Agent CLI 有新版本時 Pyloxa 會告訴你，也可以幫你更新。

## 重要：Gemini CLI 0.66.0 以後的版本

Pyloxa 只用你自己的付費 Gemini API Key 執行 Gemini CLI，不使用 Google 帳號登入，也不使用 Google AI Pro 或 Ultra 訂閱。Gemini CLI 0.66.0 改變了讀取系統設定的方式，Pyloxa 0.1.3 以前的版本因此無法再強制這一點：如果你在 Gemini CLI 用 Google 帳號登入過，交給 Gemini 的工作可能改用那個登入，而不是你的 API Key。

Pyloxa 0.1.4 重新強制只用 API Key：

- 每次執行 Gemini 都使用 Pyloxa 另外建立、執行完就刪除的設定資料夾，只允許 API Key 認證。你在 `~/.gemini` 的 Google 登入不會被載入。
- 專案的 `.gemini/settings.json` 指定了其他認證方式時，Pyloxa 不會在這個專案執行 Gemini，並說明原因。
- 我們用 Gemini CLI 0.66.0，在 Gemini 設定選了 Google 帳號登入的電腦上測試過：Pyloxa 仍然只用 API Key。

更新之前，請不要從 Pyloxa 0.1.3 以前的版本把工作交給 Gemini CLI 0.66.0 以後的版本。

## 新功能

- **CLI 的新版本**：「連線」頁會顯示 Claude Code、Codex CLI 或 Gemini CLI 有新版本、Pyloxa 驗證到哪一版，並連到官方的更新說明。CLI 的版本和上次開啟 Pyloxa 時不同時，會有一則提示。
- **一鍵更新 CLI**：有更新的已驗證版本時，按「更新到 x.y.z」並確認後，Pyloxa 會執行該 CLI 官方的安裝命令：原生安裝的 Claude Code 用 `claude install`，npm 安裝的用 `npm install -g`。CLI 有工作在執行時不會更新。Pyloxa 判斷不出安裝方式時，改為顯示可以複製的命令。
- **已驗證版本不必等 Pyloxa 發新版**：Pyloxa 查詢新版本時會一起向 GitHub 讀取一份小小的相容性目錄，新驗證的 CLI 版本、模型建議與公告不必等 Pyloxa 發新版就能送到你手上。
- **Skills 矩陣**：「Skills」頁改成每一列是一個 Skill、每一欄是一個 Agent，以 `~/.agents/skills` 的 Skills 庫為基準比對；每一格標示已同步、已安裝、內容不同或沒有。點 Skill 可以閱讀它的 `SKILL.md`、查看資料夾內的檔案，或在檔案總管中顯示。
- **更新後看看改了什麼**：更新後會有一則提示連到 pyloxa.com 的改版紀錄，新版本提示也多了「看看改了什麼」。完整紀錄在 [pyloxa.com/zh-TW/changelog](https://pyloxa.com/zh-TW/changelog/)。

## 隱私與安全

- 相容性目錄和新版本查詢一起向 GitHub 讀取，在啟動時和每 12 小時各一次；只送出這兩個查詢，不含任何專案或使用資料。兩者都可以在「設定 → 通知與更新」關閉。
- 一鍵更新改的是你在 Pyloxa 以外也在用的同一個 CLI，只會執行確認視窗上顯示的官方安裝命令。
- 在 Pyloxa 執行的 Gemini 不再載入你自己的 Gemini 設定、MCP 伺服器、擴充與 hooks，這些執行也會關閉 Gemini 的使用統計。
- 免費版的「Skills」頁只讀取 Skills 資料夾，不做任何修改。新增、同步、編輯與移除 Skill 屬於付費版，目前還沒推出，這些按鈕會顯示鎖頭。

## 升級

直接執行新的安裝檔覆蓋舊版即可。存在 `%APPDATA%\Pyloxa` 的執行紀錄、專案、設定與保存的 API Key 都會保留。

## 已知限制

- 只支援 Windows 10 與 11（64 位元）。
- 安裝檔沒有程式碼簽章，SmartScreen 可能跳出警告；請按「其他資訊」，再按「仍要執行」。
- Pyloxa 本身不會自動更新。有新版本時 Pyloxa 會提示你。
- Codex 透過 `codex exec` 在它的沙箱內執行。在 Windows 上，這個沙箱通常無法建置專案或安裝套件，所以 Codex 的成果以你的驗證命令驗收。
- Gemini CLI 是實驗性支援：不能擔任大腦，在無人值守模式下也不能執行命令。它內建的子 Agent 可能用掉很多 token：我們測試時，一個呼叫了子 Agent 的單檔工作用了約 34 萬 token。
- 已測試 Claude Code 2.1.316–2.1.318、Codex CLI 0.166.0，以及 Gemini CLI 0.42.0 與 0.66.0。
