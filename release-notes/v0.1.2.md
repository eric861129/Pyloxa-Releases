# Pyloxa 0.1.2

Three agents work together out of the box, Gemini CLI joins as an experimental option, and a plan can run two tasks at once.

## What's new

- **A default flow for three agents.** New installs start with Claude Code as the brain, handling frontend work and video editing; Codex handling backend work and image generation; and Gemini handling writing and docs. If an agent isn't set up, its tasks go to the brain, and the plan preview says why. Every rule can be changed or deleted on the **Routing rules** page. If you already use Pyloxa, click **Apply the default flow** there; your existing rules are kept.
- **Gemini CLI (experimental).** Connect Gemini CLI with your own paid Gemini API key on the **Connections** page. Google account sign-in and AI Pro or Ultra subscriptions are not supported. Pyloxa makes Gemini CLI use only your API key, even if your own Gemini settings choose Google sign-in. Gemini runs tasks but can't act as the brain.
- **Two tasks at once.** A plan runs up to two independent tasks at the same time, and each CLI runs at most two tasks at once. Tasks that change the same files wait for each other, and the plan card shows what a task is waiting for.
- **A guided first task.** New conversations suggest a small first task and explain the steps. If the folder isn't a git project or has no commits yet, the plan preview says so before you approve.
- **Update notice and desktop notifications.** Pyloxa tells you when a new version is out. When Pyloxa isn't in front, Windows notifications tell you when a plan is ready, a task needs you, work finishes or fails, the brain replies, or a CLI runs out of quota. Both can be turned off in **Settings**.
- **Fewer version warnings.** Patch versions in the same series as a tested version, such as Claude Code 2.1.x, no longer show an "unverified version" warning.
- **Verification record in pull requests.** When you create a pull request, Pyloxa can append what each agent result actually went through: acceptance commands, required files, write scope, phase checks and who approved them. Checks that didn't run are never shown as passed.
- **Skills inventory.** A new **Skills** page lists the skills each CLI can read and flags skills with the same name but different content.
- **Team rules in the repository.** Pyloxa reads `.pyloxa/rules.json` and `.pyloxa/commands.json` from a project. You see a preview first; rules apply to the project only when you choose, and commands still need your approval one by one.
- **Usage and feedback.** **Settings** shows your first success, completion rate, fallbacks and other counts, computed on your computer only. **Copy diagnostics** copies versions and counts for a bug report.

## Privacy

- Pyloxa asks GitHub for the latest Pyloxa version at startup and every 12 hours. Only this request is sent, with no project or usage data. Turn it off in **Settings → Notifications and updates**.
- The **Skills** page reads the skills folders of each CLI (`~/.agents/skills`, `~/.claude/skills`, `~/.codex/skills`, `~/.gemini/skills`) and of the open project. It reads nothing else in those CLI folders and changes nothing.
- Usage statistics are computed on your computer and never sent. Diagnostics contain no project names, paths, instructions, code, accounts or keys, and leave your computer only if you paste them somewhere.

## Upgrading

Run the new installer over the old version. Your run history and projects in `%APPDATA%\Pyloxa` are kept. Existing setups don't get the default flow automatically; use **Apply the default flow** on the **Routing rules** page if you want it.

## Known limitations

- Windows 10 and 11, 64-bit only.
- The installer is not code-signed. SmartScreen may warn you; choose **More info**, then **Run anyway**.
- No automatic updates. Pyloxa tells you when a new version is out; download it from the releases page.
- Codex runs through `codex exec` inside its sandbox and cannot ask for approval of single actions.
- Gemini CLI support is experimental. It can't act as the brain or resume a previous session. In unattended mode Gemini CLI offers no shell tool, so Gemini can edit files but can't run commands.
- Tested with Claude Code 2.1.316–2.1.317, Codex CLI 0.166.0 and Gemini CLI 0.42.0. Other patch versions in the same series run without a warning; a new series runs in supervised mode only, and its output format can change.
- Running two tasks at once is new. It has been tested with Claude Code and Codex CLI; if you see anything odd, please report it.

# Pyloxa 0.1.2（繁體中文）

三個 Agent 一裝好就能分工，Gemini CLI 以實驗性功能加入，計畫也可以同時執行兩個工作。

## 新功能

- **三個 Agent 分工的預設流程**：新安裝時，Claude Code 擔任大腦，負責前端與影片剪輯；Codex 負責後端與生圖；Gemini 負責文章與文件。某個 Agent 還沒設定時，它的工作交給大腦，計畫預覽會說明原因。每條規則都可以在「派工規則」頁修改或刪除。已經在用 Pyloxa 的話，到那裡按「套用預設流程」，原有的規則會保留。
- **Gemini CLI（實驗性）**：在「連線」頁用你自己的付費 Gemini API Key 連上 Gemini CLI，不支援 Google 帳號登入與 AI Pro、Ultra 訂閱。即使你自己的 Gemini 設定選了 Google 帳號登入，Pyloxa 也會讓 Gemini CLI 只用你的 API Key。Gemini 可以執行工作，不能擔任大腦。
- **同時執行兩個工作**：一個計畫最多同時執行兩個互不依賴的工作，每個 CLI 最多同時兩個。會改到同一些檔案的工作會互相等待，計畫卡會說明它在等什麼。
- **第一個工作的引導**：新對話會推薦一個範圍小的第一個工作，並說明流程。資料夾不是 git 專案或還沒有 commit 時，計畫預覽會在你核准前說明。
- **新版提示與桌面通知**：有新版本時 Pyloxa 會提示你。Pyloxa 不在前景時，計畫擬好、工作等你處理、工作完成或失敗、大腦回覆、CLI 額度用盡，都會用 Windows 通知提醒你。兩者都可以在「設定」關閉。
- **版本警告變少**：和已測試版本同系列的修補版（例如 Claude Code 2.1.x）不再顯示「未驗證版本」的警告。
- **PR 說明附上驗證紀錄**：建立 pull request 時，可以附上每個 Agent 成果實際經過的檢查：驗收命令、必要檔案、寫入範圍、階段檢查與核准者。沒有執行的檢查不會寫成通過。
- **Skills 盤點**：新的「Skills」頁列出各 CLI 讀得到的 Skills，並標示同名但內容不同的。
- **放在 repo 裡的團隊規則**：Pyloxa 會讀取專案裡的 `.pyloxa/rules.json` 與 `.pyloxa/commands.json`。你會先看到預覽，規則要你選擇套用才會成為這個專案的規則，命令也照舊要你逐一核准。
- **使用統計與回報**：「設定」頁顯示第一次成功、完成率、備援接手等次數，只在你的電腦計算。「複製診斷資訊」可以把版本與次數複製到問題回報。

## 隱私

- Pyloxa 啟動時和每 12 小時會向 GitHub 查詢最新版本。只送出這個查詢，不含任何專案或使用資料。可以在「設定 → 通知與更新」關閉。
- 「Skills」頁會讀取各 CLI 的 Skills 資料夾（`~/.agents/skills`、`~/.claude/skills`、`~/.codex/skills`、`~/.gemini/skills`）與開啟中專案的 Skills 資料夾，不讀取這些 CLI 資料夾裡的其他內容，也不做任何修改。
- 使用統計只在你的電腦計算，不會傳送。診斷資訊不含專案名稱、路徑、指示、程式碼、帳號或金鑰，只有你自己貼到其他地方時才會離開你的電腦。

## 升級

直接執行新的安裝檔覆蓋舊版即可。存在 `%APPDATA%\Pyloxa` 的執行紀錄與專案會保留。原本的設定不會自動加入預設流程；想要的話，到「派工規則」頁按「套用預設流程」。

## 已知限制

- 只支援 Windows 10 與 11（64 位元）。
- 安裝檔沒有程式碼簽章，SmartScreen 可能跳出警告；請按「其他資訊」，再按「仍要執行」。
- 不會自動更新。有新版本時 Pyloxa 會提示你，請到版本頁下載。
- Codex 透過 `codex exec` 在它的沙箱內執行，無法逐一核准單一動作。
- Gemini CLI 是實驗性支援：不能擔任大腦，也不能接續上一次的 session。Gemini CLI 在無人值守模式下不提供執行命令的工具，所以 Gemini 可以修改檔案，但不能執行命令。
- 已測試 Claude Code 2.1.316–2.1.317、Codex CLI 0.166.0 與 Gemini CLI 0.42.0。同系列的其他修補版不會顯示警告；換到新的系列時只能用監督模式，輸出格式也可能不同。
- 同時執行兩個工作是新功能，已經用 Claude Code 與 Codex CLI 實際測試過；如果遇到異常，請回報給我們。
