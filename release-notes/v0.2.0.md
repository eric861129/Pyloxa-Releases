# Pyloxa 0.2.0

This update lets you save your own workflows, describe a workflow in one sentence and try Pyloxa on a sample project before you use your own. It adds a verification card to every finished plan, a settings backup you can take to another computer, and a Help menu.

## New

- **Try it on a sample project first.** The setup wizard offers **Start the test drive** on its last step and, once an agent is signed in, already on its first steps; the welcome page before you have any project offers it too. If you start from an early step, the wizard closes with default settings and the getting-started checklist lists what's left. Pyloxa creates a small sample repository with a hidden rounding bug and a ready-made plan; nothing runs until you approve it. With two different CLIs, one fixes the bug and the other tests the fix (automatic in Pro; in the free version you choose **Have another agent test it**). With one CLI, Pyloxa runs the spec's tests itself. Agents can only change files in `src/`, so a passing result means the bug is really fixed. Before you start, Pyloxa shows who does what and an estimate of the agent turns, tokens and time it will take. The test drive needs git and Node.js, and it uses your own subscriptions or API keys like any other task.
- **A verification card for every finished plan.** Below a finished plan, **Verification card** shows what was checked: who did each task, whether it was cross-tested, the commands Pyloxa ran itself and their results. You can copy it as Markdown. The same card now replaces the verification record in pull request descriptions. An optional last line says “Verified with Pyloxa” only when every result passed the commands Pyloxa ran and every gate passed.
- **My workflows (Pro).** On the Workflow page, **Save as my workflow** keeps your current dispatch mode, brain review, cross-testing, worktree setting, phases and division of work under a name, up to 20. Each project can use a different workflow, and your own rules for a project still come first. Each workflow keeps its last 10 versions: compare any two, or restore one. Without Pro, projects use the global settings and your workflows are kept.
- **Describe a workflow in one sentence (Pro).** Choose **Describe it** on the Workflow page and write what you want, for example “write a spec first and wait for my approval; backend goes to Codex; the brain reviews everything”. The brain drafts a workflow and lists what it couldn't do. You see exactly which settings would change before you apply it to the global settings or save it as one of your workflows.
- **Take your settings to another computer.** **Settings → Backup and transfer** exports your profiles, global rules, brain and dispatch preferences, prompt templates, global shared memory, skills library, appearance and your workflows to one file, and imports it on another computer with a preview of every change. API keys, sign-ins and paths on this computer are never exported. Before an import, Pyloxa backs up this computer's settings, and **Restore a backup** brings back any of the last five. Export and import are free; Pro settings in the file are kept and pause without Pro.
- **Dispatch packs carry workflows (Pro).** A dispatch pack can now include your workflows, and importing one can set the project to use it. What older packs called “workflow and conventions” is now **Conventions**. Packs made by 0.1.10 still import.
- **Phase progress on plan cards.** After you approve a plan with more than one phase, a bar above the plan shows each phase's status and where the plan is. Click a phase to jump to it.
- **Help.** The **Help** menu and the Pyloxa menu in the title bar open **Pyloxa Help** at pyloxa.com/help/, in English or Traditional Chinese.

## Changes

- **The setup wizard starts with how Pyloxa differs** from running several agent sessions yourself: it splits work across vendors, runs your tests itself, hands work over when quota runs out and never touches your working folder. It also points out that small changes can go straight to one agent from below the message box.
- The setup wizard and plan cards now match how Pyloxa works. The welcome page no longer says Pyloxa has no server: your code and agent replies never pass through Pyloxa's servers, and anonymous usage statistics stay off unless you turn them on. The wizard points to the **Workflow** page instead of the old Routing Rules page. In Pro, plan cards no longer say “at most two at a time”: tasks run as many at once as each connection allows.
- When the brain can't draft a workflow, Pyloxa says why and what to do next.
- Interface languages other than Chinese no longer show Chinese punctuation in a few places.
- In the free version, workflows drafted by the brain never apply automatic mode.

## Privacy

- No new network requests. **Pyloxa Help** opens pyloxa.com in your browser.
- The test drive's sample repository stays in Pyloxa's data folder on your computer, under `test-drive`.

## Upgrading

Run the new installer over the old version. Your run history, projects, settings, shared memory and saved API keys in `%APPDATA%\Pyloxa` are kept. The database stays at version 21, so you can go back to 0.1.10 with the same data; 0.1.10 doesn't show your workflows and can't import dispatch packs that contain them.

## Known limitations

- Windows 10 and 11, 64-bit only.
- The installer is not code-signed. SmartScreen may warn you; choose **More info**, then **Run anyway**.
- No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
- Codex runs through `codex exec` in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
- Test code that an agent writes still runs outside the sandbox when your verification commands run it, without your keys in its environment. Review the changes of tasks that add or change tests.
- Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
- Agent Teams is experimental.
- Pyloxa Help is in English and Traditional Chinese only for now.
- Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

# Pyloxa 0.2.0（繁體中文）

這次更新可以存下自己的工作流程、用一句話建立流程，也可以先拿範例專案試駕，再用在自己的專案上。每個完成的計畫都多了驗證報告卡，設定可以備份帶到另一台電腦，選單也多了說明文件。

## 新功能

- **先用範例專案試駕。** 設定精靈的最後一步有「開始試駕」，已經登入 Agent 時，前面幾步就有；還沒有任何專案時的歡迎頁也有。從前面的步驟開始時，精靈以預設值結束，入門清單會列出還沒做的事。Pyloxa 會建立一個藏了四捨五入 bug 的小範例 repo 和事先寫好的計畫，你核准之前什麼都不會執行。有兩個不同的 CLI 時，一個修 bug、另一家測試修好了沒（Pro 自動；免費版由你按「交給另一個 Agent 測試」）；只有一個時，由 Pyloxa 自己執行規格裡的測試。Agent 只能改 `src/` 裡的檔案，所以結果通過就代表 bug 真的修好了。開始前會顯示誰做、誰測，以及估計的 Agent 回合數、tokens 與時間。試駕需要 git 與 Node.js，和其他工作一樣用你自己的訂閱或 API Key。
- **每個完成的計畫都有驗證報告卡。** 計畫完成後，下方的「驗證報告卡」列出檢查了什麼：每個工作由誰做、有沒有交叉測試、Pyloxa 自己執行的命令與結果，可以複製成 Markdown。PR 說明裡的驗證紀錄也換成同一張報告卡。最後一行的「Verified with Pyloxa」要你打開才加，而且只有每個成果都通過 Pyloxa 執行的命令、Gate 也都通過時才會這樣寫。
- **我的流程（Pro）。** 在「工作流程」頁按「存成我的流程」，把目前的派工模式、大腦驗收、交叉測試、worktree、階段與分工存成一個有名字的流程，最多 20 個。每個專案可以使用不同的流程，你為專案另外設的規則仍然優先。每個流程保留最近 10 個版本，可以比較任兩版或還原到某一版。沒有 Pro 時專案照全域設定，存好的流程會保留。
- **用一句話建立流程（Pro）。** 在「工作流程」頁按「用一句話建立」，寫下你想要的做法，例如「先寫規格，我核准後再開發；後端交給 Codex；全部都要大腦驗收」。大腦擬好一個流程，並列出做不到的地方。套用到全域設定或存成我的流程之前，會先列出哪些設定會改變。
- **設定帶著走。** 「設定 → 備份與搬移」把 Profile、全域規則、大腦與派工偏好、常用指令範本、全域共用記憶、Skills 庫、外觀與我的流程匯出成一個檔案，在另一台電腦匯入時會先預覽每一項變更。API Key、登入資料與這台電腦的路徑一律不匯出。匯入前會先備份這台的設定，「還原備份」可以回到最近 5 份中的任一份。匯出與匯入免費；檔案裡的 Pro 設定照存，沒有 Pro 時暫停。
- **派工包可以帶我的流程（Pro）。** 派工包可以附上你的流程，匯入時可以順便讓這個專案使用。舊派工包的「流程與慣例」改稱「慣例」。0.1.10 做的派工包照常能匯入。
- **計畫卡上的階段進度。** 核准有兩個以上階段的計畫後，計畫上方會顯示每個階段的狀態與目前在第幾段，點一段就捲到那個階段。
- **說明文件。** 「說明」選單與標題列的 Pyloxa 選單可以開啟 pyloxa.com/help/ 的「說明文件」（英文或繁體中文）。

## 調整

- **設定精靈一開始就說明和自己開好幾個 Session 有什麼不同**：跨家分工、Pyloxa 自己跑測試、額度用完換手、不碰你的工作資料夾。也提醒小修改可以在輸入框下方直接交給某個 Agent。
- 設定精靈與計畫卡的文字跟上 Pyloxa 現在的做法。歡迎頁不再說 Pyloxa 沒有伺服器：你的程式碼與 Agent 的回覆不會經過 Pyloxa 的伺服器，匿名使用統計預設關閉、你開啟才會傳送。精靈改指向「工作流程」頁，不再是舊的「派工規則」頁。Pro 的計畫卡不再寫「最多同時兩個工作」：同時進行的數量只受各條連線的上限限制。
- 大腦擬不出流程時，Pyloxa 會說明原因與下一步。
- 中文以外的介面，不再有幾處出現中文標點。
- 免費版裡，大腦擬好的流程不會套用自動模式。

## 隱私

- 沒有新的網路請求。「說明文件」是用瀏覽器開啟 pyloxa.com。
- 試駕的範例 repo 留在你電腦上 Pyloxa 資料夾的 `test-drive` 裡。

## 升級

直接執行新的安裝檔覆蓋舊版即可。存在 `%APPDATA%\Pyloxa` 的執行紀錄、專案、設定、共用記憶與保存的 API Key 都會保留。資料庫維持第 21 版，所以可以用同一份資料回到 0.1.10；0.1.10 看不到我的流程，也不能匯入含有流程的派工包。

## 已知限制

- 只支援 Windows 10 與 11（64 位元）。
- 安裝檔沒有程式碼簽章，SmartScreen 可能跳出警告；請按「其他資訊」，再按「仍要執行」。
- Pyloxa 本身不會自動更新。有新版本時 Pyloxa 會提示你。
- Codex 透過 `codex exec` 在它的沙箱內執行。在 Windows 上，這個沙箱通常無法建置專案或安裝套件，所以 Codex 的成果以你的驗證命令驗收。
- Agent 寫的測試程式，在驗證命令執行它時仍在沙箱外執行（環境裡沒有你的金鑰）。新增或修改測試的工作，請看過變更再接受。
- Gemini CLI 是實驗性支援：不能擔任大腦或交叉測試的測試者，在無人值守模式下也不能執行命令。
- Agent Teams 是實驗功能。
- 說明文件目前只有英文與繁體中文。
- 已測試 Claude Code 2.1.318、Codex CLI 0.166.0，以及 Gemini CLI 0.66.0 與 0.67.0。
